## 先配置数据库

在微信开发者工具顶部点击云朵图标，进入云开发控制台。确认左上角环境为 wordtune，环境 ID 为 wordtune-d4gl8hb7gf0d380b7。左侧点「数据库」，上方点「集合管理」。现有 8 个集合无需重复创建。以下为重建时的操作说明。

集合名称右侧的「＋」用于新建集合。先创建 rooms，权限设为「所有用户不可读写」；如果页面没有这个选项，先创建后进入该集合的「数据权限」，按下面 JSON 保存。不要添加测试记录。

```json
{ "read": false, "write": false }
```

然后依次创建 room_codes、room_members、round_submissions、room_events、operation_receipts、operation_limits，使用同样的禁止客户端读写权限。

最后创建 player_room_views，进入「数据权限」→「自定义安全规则」，保存：

```json
{ "read": "doc._openid == auth.openid", "write": false }
```

在「索引管理」中配置 [数据库配置.json](数据库配置.json) 列出的索引。rooms 上的 status_expiry 为 status 升序加 expiresAt 升序，非唯一；过期清理相关集合使用 expiresAt 升序、非唯一。不要删除内置 _id 索引。

## 部署函数

所有集合及权限配置完成后执行。部署沿用已有微信体验版环境，不升级套餐、不创建新付费环境。

3. 右键 gameApi，选择「上传并部署：云端安装依赖」。函数入口为 index.main；当前实际运行环境为 Node.js 16.13，已通过真实调用。
4. 在云函数配置中将超时设为 60 秒，供定时分批清理使用；单个数据库事务自身仍需在官方限定时间内完成。
5. 右键 gameApi，使用「上传触发器」上传 config.json；如当前工具在部署时已同步触发器，在控制台确认只存在一个 cleanupExpiredRooms 即可。周期为每 10 分钟，UTC+8。
6. 在云开发控制台「云函数」确认 gameApi 已部署成功。保存源码不代表部署完成；触发器也需单独确认。

## 客户端调用与错误处理

统一调用 `wx.cloud.callFunction({name:'gameApi', data:{action, ...参数}})`。成功 envelope 为 `{ok:true,data:快照}`，业务失败为 `{ok:false,code}`。不要在云控制台编造 OpenID 来做双人测试；真实调用应由小游戏会话发出。

| action | 参数 |
| --- | --- |
| createRoom | requestId |
| joinRoom | requestId、roomCode（6 位字符串） |
| submitWord | requestId、roomId、expectedRound、expectedAttempt、word |
| readyNextRound | requestId、roomId、expectedRound、expectedAttempt |
| updateProfile | requestId、profile: {nickname, avatar}；不要求已有房间 |
| getHistory | roomId、可选 beforeSequence；返回 events 和 hasMore |
| leaveRoom | requestId、roomId |
| resumeRoom | roomId 可省略，省略时查询当前成员指针 |
| heartbeat | roomId |

requestId 为每次新操作生成的 16–80 位字母、数字、下划线或短横线字符串。同一操作因响应丢失而重试时复用原编号；新操作应换编号。

常见业务结果：ROOM_NOT_FOUND、ROOM_EXPIRED、ROOM_CLOSED、ROOM_FULL、ACTIVE_ROOM_EXISTS、ALREADY_SUBMITTED、STALE_ATTEMPT、STALE_ROUND、TOO_MANY_REQUESTS。出现 SERVICE_BUSY 或调用失败时暂停云端验证，记录错误码、触发操作和时间，不记录词语及完整身份。

# 第三阶段：数据库设计

2026-11-04。8 个集合和权限已配置；新增公开结果历史与玩家资料。rooms 状态新增 revealed，表示双方词语已公开、等待双方继续。

配置清单见 [数据库配置.json](数据库配置.json)。所有时间均为服务端毫秒时间戳。所有集合保留数据库内置的唯一 `_id` 索引。

| 集合 | 文档 ID | 主要数据 |
| --- | --- | --- |
| rooms | 服务端生成的 32 位随机 roomId | 成员 OpenID 列表、6 位字符串房间号、status、round、attempt、submitted、ready、lastSeenAt、version、sequence、latestEvent、expiresAt |
| room_codes | 6 位字符串，允许前导零 | roomId、expiresAt；占用及过期复用均在事务中处理 |
| room_members | 服务端计算的用户身份摘要 | openid、roomId、seat、active、updatedAt、profile；无房间时也可保存昵称头像 |
| round_submissions | roomId_轮次_尝试号_席位 | 第一位提交者的 word、requestId、createdAt、expiresAt；第二人的词语在事务内存中比较，无须额外落库 |
| room_events | roomId_事件序号 | sequence、type、round、attempt、createdAt、expiresAt；mismatch/matched 有按席位排序的 words，matched 另有 matchedWord |
| player_room_views | roomId_席位 | _openid、ownSeat、玩家在席/提交/准备/最近活跃状态、轮次、尝试号、latestEvent、version、expiresAt；没有成员身份列表和未公开答案 |
| operation_receipts | 用户与请求编号的摘要 | scope、roomId、createdAt、expiresAt；不保存输入词语或答案指纹 |
| operation_limits | 用户与操作类别的摘要 | windowStart、count、expiresAt；加入每分钟 12 次、建房每分钟 6 次、其他操作每分钟 120 次 |

## 权限

除 player_room_views 外，所有集合统一使用：

```json
{ "read": false, "write": false }
```

player_room_views 使用自定义安全规则：

```json
{ "read": "doc._openid == auth.openid", "write": false }
```

前端必须带所属用户条件查询；使用官方支持的 `{openid}` 占位符，不必从客户端传入身份值：

```js
const watcher = wx.cloud.database().collection('player_room_views')
  .where({ _id: viewId, _openid: '{openid}' })
  .watch({ onChange, onError })
```

这里的 viewId 从 gameApi 的成功返回值获取。自定义规则下，不使用只带文档 ID 的 doc(viewId).watch()。客户端不直接读写其他集合；写入由云函数获取微信上下文身份后完成。

## 事务与恢复

关键操作共享同一 rooms 文档作为并发控制点。每个操作在同一事务中同步更新私密提交、事件、成员指针、双方视图及请求回执。SDK 仅在事务冲突时最多尝试 5 次。业务事务中不执行外部 API 调用，也不生成新的随机编号。

请求携带 requestId，提交和继续均需 expectedRound、expectedAttempt。重复请求返回当前快照，并标注 replayed；不会再次把旧答案提交进新尝试，也不能将旧尝试的继续请求应用到新结果。

首位提交者的词语只在 round_submissions。第二人提交时精确比较、删除私密提交、把双方词语写入结果事件。不匹配进入 revealed，双方确认后增加尝试号；匹配进入 matched，双方确认后增加轮次。room.history 与视图仅缓存最近 20 个结果，完整结果经成员验证后从 room_events 分页加载。旧版未保存的失败词语无法恢复。

room.profiles 与双方视图 players[].profile 保存双方头像昵称。updateProfile 从调用上下文定位本人，同时更新当前活动房间。头像允许微信 qlogo/qpic HTTPS 地址或最多 40000 字符的 JPEG data URL，昵称限制 1–16 个 Unicode 码点。自选图客户端裁剪为 96×96，资料不含 OpenID。profile.wechatAuthorized 记录客户端原生微信资料按钮成功返回完整资料后的入场状态，供启动时恢复；它是产品流程标记，不是服务端验证的微信授权凭证。

## 期限与清理

房间自创建起 24 小时有效，不自动续期。主动退出立即关闭房间并删除当前提交；离线和后台不退出、不删除词语。前台心跳最多每 30 秒更新一次，超过 2 分钟未活跃只作为 UI 提示，不释放席位。

gameApi 的 cleanupExpiredRooms 定时触发器计划每 10 分钟执行，仅可信触发器上下文可进入清理分支。每次最多关闭 25 个过期房间，并对回执、限流记录、事件各清理最多 25 条过期记录。重复触发可安全重入。关闭房间与词语删除保持原子性；清理旧房间时不会清空玩家在新房间中的成员指针。

请求回执和成功事件保留至房间有效期结束后 24 小时，再由定时任务清理。rooms、视图和房间号映射的元数据暂不物理删除；后续上线前应结合隐私说明补充元数据保留策略。积压超过单批上限时需监控并调整批量与频率。上述清理尚未在云端验证，不能据此宣称实际过期词语已清除。

## 官方依据

核对日期：2026-11-03。使用原生 wx.cloud 与 wx-server-sdk 4.0.2，不引入独立 CloudBase SDK 的业务调用写法。

- [微信云函数事务](https://developers.weixin.qq.com/miniprogram/dev/wxcloud/reference-sdk-api/database/Database.runTransaction.html)：仅服务端、单文档操作、冲突自动重试、直接返回回调结果。
- [微信调用上下文](https://developers.weixin.qq.com/miniprogram/dev/wxcloud/reference-sdk-api/utils/Cloud.getWXContext.html)：函数内获取 OPENID、APPID 和 SOURCE。
- [数据库安全规则](https://developers.weixin.qq.com/miniprogram/dev/wxcloud/guide/database/security-rules.html)：查询条件应包含安全规则条件，支持 `{openid}` 占位符。
- [watch](https://developers.weixin.qq.com/miniprogram/dev/wxcloud/reference-sdk-api/database/collection/Collection.watch.html)：初始快照、onChange/onError 和 close。
- [定时触发器](https://developers.weixin.qq.com/minigame/dev/wxcloud/guide/functions/triggers.html)：config.json 配置，SOURCE 为 wx_trigger，UTC+8。
- [腾讯云开发事务说明](https://docs.cloudbase.net/database/transaction)：事务执行时间限制及避免在事务中调用外部接口。其独立 SDK 示例仅作为能力参考。

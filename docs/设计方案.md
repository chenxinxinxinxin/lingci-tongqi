# 心有灵犀：第一版设计方案（已确认）

用户于 2026-11-03 在当前对话确认设计，并要求在当前对话继续开发，不再同步原对话。确认的视觉方案为浅蓝色、可爱、静态背景，其余沿用原方案。

## 范围与实现

沿用微信小游戏、原生 JavaScript、Canvas 2D 绘制界面和微信键盘接口；云端沿用 wx.cloud、wx-server-sdk 与文档型数据库。仅双人猜词，不加入聊天、排行、商城、广告、会员或 AI。

设计确认后进入后端开发。下述云数据库规则、事务、键盘和分享方案均须在实现阶段按官方接口及真实环境验证。

## 视觉方案

竖屏，自适应手机安全区域。背景采用静态浅蓝色主题：底色为云朵蓝 #EAF6FF，可配少量固定的白色云朵、小星星和圆点；正文为深蓝灰 #29465B，主按钮为清透蓝 #64B5F6，卡片为白色，成功强调色保留柔粉。使用圆润的卡片、大按钮与简洁可爱的图案，整体清爽、柔和。Logo 保留两颗靠近的心形，通过绘制路径生成，不依赖外部素材。

背景始终静止，不使用漂浮、呼吸、水波纹、粒子或自动移动的背景效果；可爱感由配色、圆角和静态图案体现。原方案中的成功双心合并动画保留，仅在成功弹窗触发，不作为背景循环播放；其余页面、交互、玩法和技术方案保持不变。

按钮至少保留约 48 逻辑像素的触控区域。状态用文字配合颜色，不只用颜色表达。键盘出现时保持输入内容与提交区域可见，避免被遮挡。应用进入后台时停止装饰动画。

## 页面与按钮

### 首页

从上到下：双心 Logo、心有灵犀、说明「各想一个词，看看是否想到一起」、创建房间主按钮、加入房间次按钮、三步玩法说明。

创建时显示加载状态并防止重复点击；成功进入房间。存在可恢复房间时展示「继续上次房间」，经服务端验证后恢复。失败显示可理解的错误与重试按钮。

### 加入房间

返回按钮、标题「找到你的搭档」、6 位房间号输入区、加入房间按钮、错误提示。输入作为字符串处理，允许前导零，只接受 6 位数字。校验通过才允许请求加入。分享链接带房间号时只预填，不自动绕过加入确认或服务端校验。

房间无效、关闭、过期、已满分别提示；重复加入由服务端返回自己的已有席位，房主不会占据第二席。

### 房间等待

顶部：返回首页、房间号、复制按钮。中央：我与搭档两张状态卡；搭档缺席时显示「等待搭档加入」。底部：邀请微信好友、退出房间。

复制使用微信剪贴板接口；邀请使用小游戏分享接口。分享取消不改变成员状态，不把分享回调视为加入成功。返回首页不等于退出；「退出房间」需确认后才请求服务端结束成员关系。

### 正在猜词

顶部显示房间号、轮次和尝试次数。两张玩家卡只显示「正在想词」「已提交」。下方是自己的词语输入区及提交按钮，再下方是退出入口。

未提交：显示「想一个词，准备好就提交」。本人已提交：锁定输入与按钮，显示「已提交，等待对方」。对方先提交：显示「对方已提交，等待你提交」。双方词语仅 trim 首尾空白，内部字符严格区分；空内容拒绝，建议最大 20 个 Unicode 码点。

网络请求未确认时显示「正在确认提交结果」，恢复后查询自己的提交状态。不能仅凭本地超时解锁答案重填。每次请求带请求编号、轮次和尝试号，旧请求不能提交进新尝试。

### 不匹配

双方完成后只展示「还没有想到一起，再试一次！」，不展示任何答案。服务端同一事务删除两份私密提交、增加尝试号、重置提交状态并记录事件。输入区随新尝试恢复，提示不阻塞新输入。

### 成功弹窗及下一轮

展示双心合并动画、「心有灵犀！」、共同词语及「再来一轮」。第一版默认静音，不添加声音资源。

成功后输入区不再接受本轮提交。本人点击下一轮后按钮改为「已准备，等待搭档」；对方先准备则显示「对方已经准备好下一轮，等待你确认」。双方都准备后，服务端增加轮次、尝试号归 1、清除准备状态并开始。

成功事件持久化并按事件 ID 去重，断线回到成功轮次仍能展示；已开始下一轮后不回放旧成功弹窗。

## 房间有效期与离线恢复

建议房间自创建起有效 24 小时，界面显示有效期；第一版不自动续期。后台、断网和重新加载不自动退出、不删除已提交答案。恢复前台时重新校验成员与期限，然后读取快照并建立唯一监听。

超过 2 分钟未收到心跳只标记「可能离线」，不清除提交也不让其他人顶替席位。心跳仅在前台按需更新；断网提示不依赖另一方词语。

主动退出会关闭整个双人房间并清除私密提交，双方都需重新建房；不在游戏中途替换搭档。过期后拒绝新业务操作；后台清理负责删除遗留私密词语，清理任务及其运行验证必须完成后才可上线。

## 数据与权限设计草案

| 集合 | 主要字段 | 客户端访问 |
| --- | --- | --- |
| rooms | 随机 roomId、6 位 roomCode、ownerId、memberIds、status、round、attempt、submitted、ready、version、expiresAt、eventSeq | 全部禁止，仅云函数访问 |
| room_codes | _id 为 6 位字符串、roomId、expiresAt | 全部禁止；服务端事务保留和复用过期号码 |
| room_members | roomId、openid、seat、joinedAt、lastSeenAt、active | 全部禁止；服务端识别身份 |
| round_submissions | roomId、round、attempt、seat、word、requestId、createdAt | 全部禁止；结算时事务删除 |
| room_events | roomId、sequence、type、round、attempt、matchedWord（仅成功）、createdAt | 全部禁止；保留恢复所需事件，不保存失败答案 |
| player_room_views | _id、_openid、roomId、roomCode、两席状态、轮次、尝试、结果事件、准备状态、expiresAt、version | 仅所属玩家可读及 watch；客户端不可写 |
| operation_receipts | caller、requestId、operation、result、expiresAt | 全部禁止；云端去重 |

为避免把所有房间公开，采用每个玩家一份状态视图：云函数在同一事务内更新房间和两份视图，每份视图都只含可展示的状态。客户端只监听自己的视图，依靠“仅本人可读，客户端不可写”的规则隔离，不通过猜中房间号读取其他房间。

_openid 字段由云函数根据调用上下文写入，不能接收客户端提供的值。客户端安全规则、云函数调用权限、非成员拒绝访问和实际 watch 均需实测，不能只凭字段命名认为隔离生效。

## 云端操作与并发

createRoom、joinRoom、submitWord、readyNextRound、leaveRoom、resumeRoom 和心跳均从调用上下文识别玩家。房间号只是加入凭据，非查询内部状态的授权；加入请求需限流，失败不返回成员身份。容量只有两个席位。

关键操作在服务端事务中读取并修改同一房间记录。事务只按确定文档 ID 操作，避免在事务内查询列表或调用外部接口。房间号占用、成员席位、提交、结算、私密记录删除和视图更新保持原子性。事务冲突按 SDK 约定重试。

提交携带 expectedRound、expectedAttempt 和 requestId。成员每次只允许一份提交；第二人提交的事务完成精确比较并且只结算一次。重复请求通过回执返回已有结果；不能因首次响应丢失而把同一个词提交到下一次尝试。

## 必须验证的测试

- 初始快照、两人先后及同时提交、失败自动新尝试、成功弹窗、单方及双方下一轮准备。
- 两个不同微信身份真测，单账号测试不得作为双人同步证据。
- 未完成提交时双方均无法获取对方词语，失败后无答案残留，非成员无法获取内部状态。
- 重复提交、旧轮次请求、响应丢失、断网重连、后台恢复、主动退出和房间过期。
- watch 出错后退避重连，恢复前台只创建一个监听，离开房间关闭监听，避免连接泄露。
- 房间号前导零、并发加入、同账号重复加入、房间满员、无效号码、限流及过期号码复用。

上述为测试计划，尚未执行，不代表功能已完成。

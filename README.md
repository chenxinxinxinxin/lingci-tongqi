# 灵词同契 / Lingci Tongqi

双人猜词微信小游戏：各自想一个词，双方提交后一起揭晓，并根据此前的词语继续寻找共同答案。

作者：**cline** · 博客：[cline.blog](https://cline.blog) · [GitHub 仓库](https://github.com/chenxinxinxinxin/lingci-tongqi)

## 功能与状态

- 双人房间、6 位房间号及邀请入口。
- 双方提交后公开各自词语，双方确认后继续；保留可分页查看的结果历史。
- 微信头像昵称授权入场，房间内互相展示资料。
- 大厅和房间顶部提供退出入口，退出后返回大厅。
- 事务结算、请求幂等重试、断网恢复及实时状态监听。

用户已完成双人真机功能验收。目前等待审核上线，尚无正式公开体验入口。分享曾出现微信平台限制提示，原因及解除状态尚未确认；本地测试不代表分享已恢复。正式上线后将在此补充小游戏码。

## 本地运行与部署

这是微信小游戏源码，不能直接作为普通网页部署。需要 Node.js、Git、微信开发者工具，以及自己的微信小游戏 AppID 和云开发环境。

1. 克隆仓库，用微信开发者工具导入项目根目录，项目类型选择小游戏。
2. 将 `project.config.json` 的 `appid` 替换为自己的小游戏 AppID，将 `game.js` 的 `env` 替换为自己的云环境 ID。仓库保留的原项目标识不是密钥，也不授予云端访问权限；请勿将其用于自己的部署。
3. 按 [数据库配置](docs/数据库配置.json) 和 [部署说明](docs/云函数部署.md) 创建自己的集合、规则及索引。
4. 在 `cloudfunctions/gameApi` 运行 `npm ci --ignore-scripts`，或部署时选择云端安装依赖；上传云函数和清理触发器，核对运行时及实际执行日志。
5. 配置自己账号的隐私保护指引，使用两个真实微信身份进行预览验证。

不要在源码中填写 AppSecret、云平台密钥、访问令牌或真实用户数据。`project.private.config.json`、环境变量文件和 `node_modules` 不纳入版本管理。部署文档中的原环境名称仅为历史记录，应替换成自己的配置。

## 本地验证

在项目根目录运行 `npm test` 验证隔离的业务状态机、并发重试和恢复行为，运行 `npm run check` 检查 JavaScript 语法与 JSON 配置。测试无需云端凭证，也不会读写真实房间。

部署前如需重新安装函数依赖，在 cloudfunctions/gameApi 中运行 `npm ci --ignore-scripts`；开发者工具上传时可选择云端安装依赖。根目录测试仅使用 Node.js 内置工具。

详见 [测试报告](docs/测试报告.md)。本地测试不替代真实双人和真机测试。没有提交审核或正式发布。

客户端会临时缓存本人尚未确认的操作（包括自己的待提交词语），响应确认后立即移除；用于重启后使用同一请求编号重试，避免将旧词误交到新尝试。不会在客户端保存搭档的未揭晓词语。

新版玩法：双方提交后公开双方词语，停留在结果页，双方都确认后继续。结果保留在页面下方，可滑动及分页查看。首次进入必须通过微信原生按钮主动授权头像昵称，保存成功后进入大厅；拒绝授权停留在授权页。已授权资料可恢复，原有未记录授权状态的玩家需补授权一次。授权后可在首页或自己的玩家卡修改资料。大厅和房间顶部均有退出入口，确认退出后关闭房间并返回大厅。房间有效期内可恢复记录；旧版已丢弃的失败词语无法补回。
